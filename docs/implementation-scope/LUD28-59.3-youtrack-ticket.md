## 🏗️ Implementierungsplan

**Vollständiger Plan:** [docs/implementation-scope/LUD28-59.3-implementation-plan.md](https://github.com/YOUR_REPO/blob/main/docs/implementation-scope/LUD28-59.3-implementation-plan.md)

### Phase 1a: Auth-Domäne (Tag 1-2)
- `User` (UUID PK, 1:1 → UserRights, 1:n → UserAllowedTerminal)

- `SpeechHumanInput`, `SpeechTestInput`
- `Category` (zentrale Kategorisierung)

### Phase 3: HomeAssistant (Tag 5-8)
- `HaSnapshot`, `HaArea`, `HaDevice`
- `HaEntity` (natürlicher PK: `entity_id`, Domain-Enum)
- `HaEntityState`, `HaEntityAttribute` (EAV-Modell)

### Phase 4: Integration (Tag 8-9)
- Module-Registrierung in `app.module.ts`
- TypeORM-Config (`database.config.ts`)
- Compilation-Check

## ✅ Akzeptanzkriterien

1. **Vollständigkeit**
   - [ ] Alle 18 Entities implementiert
   - [ ] Alle Felder aus Specs vorhanden
   - [ ] Alle Relationen definiert (bidirektional)

2. **TypeORM-Compliance**
   - [ ] Korrekte Decorators (`@Entity()`, `@Column()`, `@ManyToOne()`, etc.)
   - [ ] UUID-PKs via `@PrimaryGeneratedColumn('uuid')`
   - [ ] Indizes gemäß Specs

3. **Naming Conventions**
   - [ ] FK-Namen: `fk_<from>__<to>__<column>`
   - [ ] Index-Namen: `ix_<table>__<column>`
   - [ ] Unique-Namen: `uq_<table>__<column>`

4. **Compilation Success**
   - [ ] `npm run build` ohne Fehler
   - [ ] Keine TypeScript-Linter-Warnungen

5. **Dokumentation**
   - [ ] JSDoc-Kommentare für Entities
   - [ ] Verification-Script funktionstüchtig
